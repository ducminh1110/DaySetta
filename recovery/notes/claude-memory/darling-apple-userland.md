2026-10-29: Apple's own `/bin/echo` from BaseSystem 26.6 runs on Darling (x86 box) with Apple's whole userland from the shared cache; only `libsystem_kernel` is Darling's (cache "root" override via dyld patch tables).

**Why:** the hybrid plan ([[daylight-windowserver]]) needs real AppKit/SkyLight; ipsw-extracted dylibs can't be mixed with Darling libs, so the route is a ported dyld that maps the real cache.

**How to apply:**
- dyld port: `~/dyld-1378` (both hosts; x86 box is source of truth), compat in `darling-compat/` (prelude, libamfi.h stand-in, glue, libc++18 headers, cctools-1035 mach-o headers, AV 157.2 VersionMap). Build/link scripts `/tmp/dyld_try.sh`, `/tmp/dyld_link.sh` on x86 box (copies in local scratchpad); must link with Darling ld64 + `-fno-jump-tables` (lld can't emit MH_DYLINKER).
- Installed as `/usr/lib/dyl4` in the Darling root; `use_dyl4.py` patches a binary's LC_LOAD_DYLINKER. Runner: `/tmp/dl4.sh build|run` (sets DYLD_SHARED_CACHE_DIR to ~/basesystem cache, DYLD_SHARED_REGION=private). Local `~/bin/dlast [-r]` fetches the run log and symbolizes crashes (`~/macos-re/tools/dsym.py`).
- Darling-side fixes: F_ADDFILESIGS_RETURN (fcntl.c), skywalk/exclaves/vm_reclaim/notify sources in libsyscall, macos26_exports.c, voucher_mach_msg_clear, _libkernel_functions v4-vs-v5 detection (libkernel_table.h; elfcalls from apple[]; posix_spawn uses Apple vfork), mldr apple[] ptr_munge/stack_guard/malloc_entropy, restartable ranges in-process via RTMIN+2 signal (restartable.c), darlingserver task stubs + audit token pid version, fatal-signal report with backtrace in sigexc.c.
- libdispatch-1542 (Apple OSS) built as Darling target libdispatch_apple, installed at /usr/lib/darling/macos26/usr/lib/system; dyld override dir DARLING_MACOS_OVERRIDE_ROOT. Scripts in ~/darling-port-tools (both hosts).
