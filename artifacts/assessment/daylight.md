## 3. Server architecture
- Front end: Mach (Darling) inside the guest. server/src/main_darling.c: bootstrap_check_in for com.apple.windowserver and .active (:41-45,559), com.apple.CARenderServer only with DAYLIGHT_SERVE_CA=1 (:50-52, 580). Single-threaded receive on a port set; a tick thread sends empty datagram 0x44594cff instead of timed receive because MACH_RCV_TIMEOUT lost requests (:391-441). Portable core (daylight.h, dispatch.c) has no Mach headers -> host-testable.
- Real SkyLight clients connect unmodified: connect_and_check -> GetSessionPort -> SLSNewConnection handshake, server version 600.0, first conn id 0x1103 (server/src/session.c:14-18, 129-176); docs/knowledge/TECHNICAL_DISCOVERIES.md D-02/D-03. Then CreateWindow returns 0xb0-byte shared-state memory entry (window.c:14-16; D-04).
- MIG handled with real code: 15 routines = Session 4 (GetCoreGraphicsServerVersion, GetSessionPort, NewConnectionPort, GetPortStreamOutofline: session.c:185-188), Display 4 (GetRealtimeDisplayDataShmemPort, GetEventShmem, GetDisplayShmem, GetDisplaySystemState: display.c:96-120), Window 5 (CreateWindow, SetWindowLayerContext, SetTransactionCompletion, WindowIsOrderedIn, CopySpacesForWindows: window.c:205-209), Process 2 (SetFrontProcessWithInfo, GetKeyFocusProcess: process.c:103-104). Verified by grep of dl_register. Everything else: canned replies recorded from a REAL macOS 27 Mac (dl_canned.c; docs/traces/macos27-hello2/*.log.xz are Mac-side wsprobe2 traces, header shows pid on a Mac), remapped to 26.6 ids by caller symbol (commit 9a81464); unknown -> MIG_BAD_ID counted (README trace mode).
  README says "12 recorded traces... exercised on Darling": the traces are macOS-27-on-Mac recordings, not Darling runs.
- Events: CGEvent tokenized datagrams in the connection port stream (docs/window-canvases.md "Events"; input.c), activation event type 20 + notifications 0x5e4/0x52d/0x38a/0x388/0x390.
- Surfaces: NOT IOSurface and not CGSAddSurface. Rejected explicitly (ENGINEERING_DECISIONS.md D4). Surface = memfd-backed Darling memory entry "canvas" (darling_memory_entry_create, main_darling.c:~30; msgs AttachCanvas 0x44594c01 / CanvasFlushed 02 / CanvasDetach 03). IOSurface only appears in the parked CA path: iokitd IOSurfaceRootApple stand-in (ca-render-server-status.md "Works").
- CoreAnimation path: (a) used: client renderInContext canvases; (b) parked: daylight-ca (838 l) hosting QuartzCore's CA::Render::Server, uses unexported offsets (KI-05), interposes pthread_create/dispatch_apply (KI-08); no view contents reached it.
- Compositor: CPU, by window level then flush order (a9545d4; KI-11 heuristic) -> screen.fb (64-byte header + BGRX, seqlock, server/include/framebuffer.h) + desktop.png.
- Display backend: X11 ONLY. frontends/x11/daylight-x11.c (230 l, Xlib) maps screen.fb, sends keys/pointer via a FIFO. Wayland: README headline says it, but only "to do" (window-canvases.md:63); grep finds no Wayland code. Also systemd units for noVNC/JPEG web feed (systemd/daylight-web.service, publisher; f06c69b).
- Metal: bridge interposes MTLCreateSystemDefaultDevice with a method-less stand-in; services/metal (Rust, 124 l) metal2vulkan never built (KI-13, TD D-29).

- Directly blocking real apps: KI-06 no launchd/XPC (cfprefsd, LaunchServices, usernoted); KI-03 723/738 routines only canned; KI-01 glass/CASDF; KI-07 fonts services/IME; KI-12 AX absent; KI-13 Metal; KI-14 guest wiped; KI-15 server only runs in guest.

- 26.6 x86_64 vs 27 arm64e: protocol baseline + all runtime evidence = 26.6 x86_64 (Darling/x86 only). 27 arm64e = observed on a real Apple-silicon Mac as reference only (traces, split cache 6.6 GB, 4.57M symbols). Daylight has NO arm64/arm64e execution (Darling x86_64 only), so 27 runtime = zero. Canned data comes from 27 but ids mapped to 26.6, i.e. already a cross-version bridge with unverified id drift (KI-10).
