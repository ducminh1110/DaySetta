- arm64e / PAC on this host (evidence from cache bytes, counted raw 32-bit words in /home/ubuntu/macos-re/cache-arm64e/dyld_shared_cache_arm64e.01, 131 MB; counts are upper bounds, data words may alias): RETAB 213,648; BLRAA/BLRAB 109,534; BRAA/BRAB 11,852 (+14,112 in .02); LDRAA/LDRAB 1,118; GPR PAC/AUT (DAC1xxxx) 186,875; PACIBSP 282,975; AUTIBSP 98,707; LSE atomics (LDOP/SWP) 30,302; CAS 2,260; PACIASP/AUTIASP 0.
  - HINT-space ones (PACIBSP/AUTIBSP/XPACLRI) run as NOPs on ARMv8.0: VERIFIED by ARM ARM semantics, not run here.
  - RETAB, BLRAx/BRAx, LDRAx, PACIA/AUTIA/PACGA register forms are NOT in the HINT space: on ARMv8.0 they are UNDEFINED -> SIGILL. Cache uses them heavily (above) => stripping only HINTs is insufficient.
  - LSE atomics (not in HINT space) also SIGILL here and Linux hwcap lacks `atomics`.
  - Also arm64e Mach-O chained fixups carry auth bits (key/diversity); dyld signs pointers at bind time with PAC GPR instructions (SIGILL) and stored pointers in the cache are PAC-signed: with no PAC, signed pointers must be treated as plain addresses (strip auth bits via the fixup format) or the whole cache rebased to a PAC-less variant. Exact dyld-1378 behavior when `pauth` is absent at runtime: UNKNOWN (not traced; dyld arm64e checks `__has_feature(ptrauth_*)` at compile time).
  - Required for execution here: (a) a user-mode CPU emulator with PAC+LSE (qemu-user -cpu max, not installed, apt would add it; hosts without hardware PAC run it via TCG) or (b) an AArch64 instruction rewriter/trap-emulator (SIGILL handler that decodes RETAB/BLRAA/LDRAA/PAC*/LSE and emulates; slow but feasible; no code exists) or (c) rewrite arm64e->arm64 + LSE->LDXR/STXR at load time (also unwritten). None exists on disk.
